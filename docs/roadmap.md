# 로드맵

## 1단계: 보드에 익숙해지기
- LVGL로 터치 UI 만들기 (버튼, 슬라이더, 그래프)
- Wi-Fi로 시간과 날씨를 받아오는 대시보드

## 2단계: RTOS 내부 관찰 (핵심)
"누르면 돌아간다"는 RTOS가 없어도 똑같다. 내부를 보려면 **스케줄러의 결정을 기록하고 보이게** 만든다.

### 관찰 장치
- 각 태스크가 실행 구간을 `esp_timer_get_time()`(마이크로초)으로 기록하고, 링 버퍼에 쌓는다
- 실험이 끝나면 PC로 보내 간트 차트로 그린다 (`tools/plot_trace.py`). 나중에는 보드 화면에도 그린다
- 표시하는 일 자체가 CPU를 쓴다 → 관찰자 효과. 실험 중에는 기록만 하고 출력은 나중에

### 실험 목록
| # | 실험 | 바꿔볼 것 | 차트에서 보일 것 |
|---|---|---|---|
| 1 | 같은 우선순위 두 태스크 | 둘 다 쉬지 않고 돈다 | 틱(보통 1ms)마다 번갈아 실행되는 줄무늬 = 타임 슬라이싱 |
| 2 | 우선순위 차이 + 굶주림 | 높은 쪽이 `vTaskDelay` 없이 돈다 | 낮은 쪽은 실행 안 됨. Idle까지 굶으면 태스크 워치독 리셋 |
| 3 | Blocked 상태 | busy-wait vs `vTaskDelay` | delay 중 빈자리를 다른 태스크가 채움 |
| 4 | 큐 생산자·소비자 | 생산자를 더 빠르게 | 큐가 가득 차면 생산자가 블록되는 순간 |
| 5 | 우선순위 역전 | 바이너리 세마포어 vs 뮤텍스 | 뮤텍스의 우선순위 상속이 높은 태스크 대기를 줄임 |
| 6 | 듀얼 코어 경쟁 조건 | 코어마다 한 태스크, 공유 카운터 100만 번씩 | 락 없으면 합계 < 200만. 락 걸면 정확하지만 느려짐 |
| 7 | ISR → 태스크 | 타이머 인터럽트에서 Task Notification | 인터럽트부터 태스크 실행까지의 지연 = 실시간성 |

### 한 단계 더
- `vTaskGetRunTimeStats`로 태스크별 CPU 점유율. Arduino 코어에서 막혀 있으면 ESP-IDF로 넘어갈 계기

## 3단계: 로봇과 연결
- BALA2 원격 모니터 겸 리모컨: 기울기, 모터 출력, PID 값을 실시간 그래프로. 터치 슬라이더로 PID 게인 튜닝
- ESP-NOW: 공유기 없이 ESP32끼리 직접, 낮은 지연으로 통신

## 4단계: ROS 연결
- micro-ROS로 보드를 ROS 2 노드로 만들어 PC와 토픽을 주고받는다
- 목표 구조: PC가 중앙에서 관리하고, 로봇이 겪은 상황과 대응이 늦더라도 전부 PC에 도착한다
